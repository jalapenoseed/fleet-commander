# Fleet Commander / standalone 0.9.0

Canonical checkout: /workspace/sites/fleet-commander
Branch: fleet-commander-standalone
Source base: GRIDRUNNER a9a64002ff4536eee819654cd5e45d4964765255

Current integration: preserved the newer command-shell/planet/replay/journal source while completing the camera/coach/art/audio update. `README.md` documents the 0.7/0.8 tools; `docs/SIMULATION_SCOPE.md` describes the newer lab boundaries. Old release notes below are historical (in particular, recordings can now optionally include audio and HUD).

0.9 adds three dedicated arena views (cinematic action, best fight and longest survivor), event-focused replay slow motion down to 1/8 speed, an expanded weather system with independent visual/screen/physics/audio strengths, rain/wind/gust/lightning controls, wet-airframe rendering and a low-resolution educational incompressible-flow field. Procedural sound now varies by airframe, motor count, flight load and damage, with separate drone/weather/effects buses. Art Studio can rasterize emoji locally, and the new Math & Science / Nerd Lab exposes model fidelity, live telemetry, Boolean gates, a full adder, number formats (including 1337 and 80085 presets) and opt-in fleet rules. These remain game/teaching models, not validated CFD, RF, acoustic or flight-engineering tools.

`combat-hud.js` renders activity-aware simulated target telemetry and health bars; it is not ML detection. `arena-ui.js` and `CombatSimulation.summary()` show per-team flying/total plus returning, landed and downed counts. `battle-playbook.js` validates six squad routes and feeds local game-AI orders. `art-formation.js` preserves full RGB with unique positions; `art-studio.js` implements local drawing/image conversion and explicit exact-size roster replacement. `step-sequencer.js` provides the six-track pattern and optional on-device audio-file persistence; `video-capture.js` composites the scene/HUD with selected engine audio streams and retains the latest downloadable clip. No microphone or external AI service is used.

0.8.1 regression repairs freeze the combat camera during pause, permit full-size art JSON imports, and preserve the soundtrack/tempo/pattern when replacing the roster from art. The original in-progress 0.7 work is also retained in a local Git stash checkpoint; newer upstream additions were fast-forwarded, not overwritten. Device-local saves are explicitly labeled and not cross-device cloud saves. Browser WebGL/mobile playback verification remains outstanding; automated codec tests use mocks.

24-module initial extraction, plus standalone styles and four production drone asset packs. `airframes.js` contains only mesh construction/material streaming; it no longer imports story, squadron, tasks or survival systems. `fleet-commander-core.js` owns each aircraft body, energy and command. `fleet-commander-renderer.js` instances every body with near/detail and far/proxy geometry, plus per-body beacons.

Capacity is 0–10,000. Field limits are ±1,024 m horizontal and 320 m vertical to avoid crushing large line/ring targets onto the old 440 m field bounds. Launch pads stay unique; pads intersecting obstacle footprints stage above their roofs. Social neighbors use a spatial index with at most 24 neighbors. CPU cost is still substantial at 5k/10k; defaults remain 100.

Batteries default finite, support ¼–10× consumption, addressed-group charge injection, dynamic reserve return, empty-battery emergency descent and service/relaunch. The emergency descent is a gameplay abstraction. Normal DOCK and emergency LANDED remain distinct. Test controls lock during scored rounds. Session restores reload the saved fleet setup, as before, rather than a midair simulation snapshot.

Separate local storage (`fleetcommander.*`), file kind `fleet-commander-fleet`, old `gridrunner-commander-fleet` accepted on import. Exact parent history is retained in Git, but no world/campaign executable ships with this branch. No connection to physical drones.

Verified: core games, actual DOM controls, large real body counts, energy modes and recovery, legacy JSON compatibility, complete import dependency graph, and embedded-buffer GLB assets. Browser tactical fallback inspected; GPU output unavailable in the cloud browser.

Future directions are intentionally unimplemented: larger-world missions, hardware/component building, fleet discovery/progression, multithreaded/GPU swarm computation, richer terrain and obstacle courses, multiplayer, and real music analysis. Preserve this independent game before choosing the next expansion.

0.2 Swarm Director: `show-motion.js` supplies bounded choreography targets; `director-shows.js` creates serializable scripted performances; `swarm-program.js` eases only the new show styles between timed cues. `director-camera.js` owns FPV, walking and six cinematic shots, with real aircraft subjects. `director-environment.js` builds reusable procedural backgrounds and sky/horizon lighting. `director-ui.js` owns shows, stage preferences, clean view and feature-detected canvas recording. No physical drone connection or GRIDRUNNER dependency was introduced. Director is now the default tab. Recordings are silent local browser downloads; environment preferences are browser-local, while shows save with fleet programs.

0.3 graphics: `scene-materials.js` extends standard lighting shaders with procedural surface relief/roughness/windows; `scene-postfx.js` implements capability-gated HDR/MSAA/bloom/ACES output; `range-props.js` details the existing obstacle envelopes. `director-environment.js` now owns shadowed sun/sky lighting, PMREM sky reflections, continuous terrain, instanced detail, water normals and rebuilt scenery. Quality settings persist with atmosphere preferences in `fleetcommander.director.v1`. Graphics changes do not modify drone dynamics, battery, Boids, shows, or camera attachment. The default perspective is lower with a visible horizon; grid is off by default. All runtime module imports use the 0.3.0 cache tag.

Graphics verification: `verify-graphics.mjs`, existing Director checks and real DOM UI suite passed. `scripts/export-graphics-shaders.mjs` exports resolved Three.js shaders with physical lighting, shadows, instancing, environment mapping and fog; `scripts/check-graphics-shaders.py` compiles/links them in Mesa EGL OpenGL ES 3.2. Native shader validation succeeded for 9 programs. The cloud browser reports GL_VENDOR/GL_RENDERER Disabled; complete rendered scene appearance remains device QA. Do not claim browser GPU visual validation or smooth 10k FPS.

0.4 swarm lighting: `swarm-lighting.js` owns a bounded physical point-light pool (4/8/12 visible lights by quality) with retained-slot preference and fade-in, plus one instanced ground irradiance pass for nearby low-altitude aircraft. The ground pass is deliberately approximate and is suppressed around range obstacles; it does not add shadows, GI, or mirror reflections. `aircraft-beacons.js` now renders emitters only, with derivative-filtered cores, controllable power, haze extinction and less core whitening. `scene-postfx.js` uses a 3-scale bloom pyramid and hue-preserving highlight compression. All runtime cache tags are 0.4.0.

Director has Natural / Night show / Cinematic / Aircraft inspection presets, independent EV/brightness/spill/stage/spread controls, reset, and browser-local persistence. Environment capture is invalidated only for sky/cloud changes, not each exposure-slider event. Light controls are disabled in tactical fallback. Settings do not mutate the fleet simulation; selected FPV aircraft still light surfaces while their own mesh/beacon is hidden.

Validation: complete existing simulator/UI suite passed; expanded Director DOM tests and the new 0–10,000 lighting tests passed. Native GLSL compile/link passed for 11 programs including beacons and ground pools with 12 point lights in the physical shader. Current cloud-browser inspection confirms WebGL is disabled and fallback messaging/disabled lighting controls work. No full-scene GPU screenshot or FPS claim. Next real-device QA should check nightshow colors at wide and FPV distances, low-altitude pools, quality switching and recording.

0.5 adds isolated 2–256-drone combat (`combat-simulation.js`) with locally bundled Rapier 0.20.0 WASM and its license, four formations per faction, interceptor/bomber AI, finite gravity payloads, continuous collision detection, hull damage and persistent tumbling wrecks. Physical shapes are simplified spheres and practice-building/ground boxes; decorative scenery is still non-colliding. `arena-ui.js` integrates battle controls with existing selections, lifecycle and roster locks. Normal shows retain 10,000-body capacity and unchanged flight dynamics. Exit and pagehide restore/persist the original show setup, not battle colors. New-skirmish and reset never overwrite named fleet saves.

`battle-effects.js` renders bounded particles/payloads/flash light. `arena-weather.js` supplies branching lightning and distance-delayed thunder events, respecting pause and reduced motion. `arena-audio.js` is gesture-enabled Web Audio with six rotor voices, bounded one-shots, independent gain, limiter, mute and hidden-page silence. Recordings remain silent. Pitch-black removes environmental, sun, stage, window and station emission but preserves the moon/stars and aircraft emitters. `camera-input.js` shares pointer gesture handling across mouse/touch, with pinch/button zoom and no click-after-pinch bug; free camera adds touch look plus Q/E and on-screen vertical movement. All runtime cache tags are 0.5.0.

New tests cover real physics, 256-body staging, payloads/ammo, falling wrecks, battle restore/save/pagehide, gesture cancellation, zoom bounds, free-camera movement, lightning and thunder arrival order. Shader export includes the new particle shader and a worst-case 14 point-light configuration (12 swarm + weather + blast). Cloud-browser UI and sound activation pass in tactical fallback; it still cannot render WebGL. Do not claim full-scene GPU visual QA, perceptual audio QA, or mobile combat frame rates.

0.6: `combat-ai.js` provides bounded tunables, four ready-to-run scenarios, per-faction tactics, retained target decisions, attack distribution, evasive breaks, payload egress and allied separation. Combat rounds track engaged time separately, end on active-force loss or a configurable time limit, and optionally repeat through the UI after 8 seconds of running simulation. Round replacement retains the first original show snapshot. All numeric tuning is validated; settings affect the actual control forces, collision/blast damage and cooldowns.

FPV now has clamped FOV/sensitivity/stabilization/smoothing/tilt, quaternion interpolation, observer presets and live subject switching. The existing touch gestures are unchanged. `arena-ui.js` mounts an always-visible audio/test/meter strip, compact AI launch card, collapsible tuning, and an FPV status overlay. It persists settings in `fleetcommander.arena.v1`; audio itself still requires a gesture. Audio has a louder default arena-distance mix, midrange rotor harmonics, optional playback session routing, actual context-state status, gesture-based interruption recovery and a two-tone test independent of simulation pause. Context reuse, capped voices, mute and disposal are tested. No mic permission, external service, or AI model/API was added: combat intelligence is local game AI. Runtime release tags are 0.6.0.

Validation adds `verify-combat-ai.mjs` and `verify-arena-audio.mjs`, plus expanded actual-DOM tests for one-tap presets, live tuning, subject death switching, timed repeat/pause and show restoration. Browser audio output was confirmed via the real analyser-backed meter for both active battles and paused sound tests. Actual iOS output and GPU appearance cannot be certified from this cloud browser.
